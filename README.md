# find-hidden-gem-employers

一个面向应届生和技术求职者的 Codex Skill：通过最新联网检索，发现、核验并排序真正具备细分技术、产业资源或权威资质的“小而美”雇主，同时判断用户当前是否能投、应该怎么投。

它不会因为一家公司规模小、融资多、创始人来自大厂，或拥有普通“高新技术企业”称号，就直接把它列为“小而美”。每一家进入主名单的公司都需要同时回答：

1. 为什么它适合当前用户？
2. 为什么它称得上“小而美”？
3. 证据来自哪里，强度如何？
4. 当前招聘是否匹配用户的毕业届别？
5. 用户下一步应该立即投递、联系 HR，还是暂缓核验？

## 适用场景

- 按城市、省份或城市群寻找技术型雇主；
- 面向校招、补录、实习转正或初级社招扩展公司池；
- 搜索后端、AI 应用、Agent、工业软件、机器人、智能制造、网络安全、数据基础设施等技术方向；
- 核验“专精特新”“小巨人”“产业资本投资”“高校孵化”“龙头客户”等宣传是否成立；
- 区分产品研发、定制研发、项目交付、实施、售前、驻场和人力外包；
- 根据毕业时间判断岗位是可立即投递、届别不符、仅有历史招聘，还是只能加入人才池。

不适合只查询一家已知公司的简单信息，也不适合在无法联网时生成所谓“最新公司名单”。

## 核心能力

### 1. 从自然语言建立求职画像

Skill 会提取或合理推定：

- 目标地区；
- 学历、专业和毕业阶段；
- 目标岗位与技术栈；
- 项目、研究或实习经历；
- 行业偏好；
- 公司规模和阶段偏好；
- 对外包、驻场、实施、出差和经营风险的容忍度。

若用户只给出“27 届”之类的届别，Skill 会按中国高校通常毕业季估计求职阶段，但不会伪造具体毕业日期。

### 2. 根据毕业阶段切换搜索策略

| 当前阶段 | 优先搜索方向 |
|---|---|
| 毕业前一年 7 月至毕业当年 4 月 | 秋招、提前批、春招、实习转正 |
| 毕业当年 5–8 月 | 春招补录、毁约补录、实习转正 |
| 毕业当年 9 月以后 | 初级社招、经验不限、毕业一年内、往届可投 |

Skill 不会把“目前只招下一届”误判成用户当前可投。

### 3. 建立多来源候选池

候选公司不会只来自单一招聘平台。发现阶段会综合使用：

- 国家级或省级专精特新名单；
- 制造业单项冠军及政府产业名单；
- 产业资本、产业基金和上市公司投资组合；
- 龙头企业供应商、合作伙伴和开发者生态；
- 公司官网、产品页、官方招聘页；
- 高校就业网、主流招聘平台和可信行业媒体。

典型流程是先建立约 40–80 家候选，再通过证据核验、岗位核验和风险筛选收敛到约 20–30 家。地区或赛道较窄时宁缺毋滥。

### 4. 严格区分各种企业关系

Skill 会明确区分：

- **投资**：存在真实股权、融资或投资公告；
- **控股**：存在可核验的控制关系；
- **孵化**：由高校、科研院所或产业平台提供明确孵化证据；
- **客户**：存在采购、案例或客户官方材料；
- **合作**：联合项目、生态伙伴或战略合作；
- **团队背景**：创始人或核心成员的过往履历。

客户不会被写成投资方，合作不会被写成控股，创始人的大厂经历也不会被包装成“大厂旗下”。

## “小而美”证据等级

| 等级 | 含义 | 使用方式 |
|---|---|---|
| H3 | 至少两个独立强信号，且至少一个来自一手或权威来源 | 可进入主名单 |
| H2 | 产品和技术路线明确，并有可靠资质、产业投资、客户或商业化证据 | 可进入主名单，但显示缺口 |
| H1 | 方向有潜力，但资质、股权、商业化或组织信息证据不足 | 只进入观察池 |
| H0 | 只有规模小、融资故事或泛化资质，或属于外包、长期驻场、伪研发 | 排除 |

H 等级表示“小而美证据成立程度”，不是公司好坏或当前可投性的综合分数。

## 双评分体系

Skill 将雇主质量和当前招聘机会分开评分，避免“一家公司很好”被误解为“现在就能投”。

### 雇主匹配分（100 分）

- 目标岗位与技术栈：25 分；
- 技术含量与研发属性：20 分；
- 细分行业竞争力：15 分；
- 客户与商业化：10 分；
- 成长与培养：10 分；
- 规模与组织适配：10 分；
- 经营稳定性：10 分。

### 当前机会分（100 分）

- 目标届别资格：35 分；
- 岗位开放状态：25 分；
- 岗位匹配程度：20 分；
- 初级或应届适配：10 分；
- 信息新鲜度：10 分。

最终行动标签包括：

- `立即投递`
- `联系HR确认后投`
- `投初级社招/补录`
- `加入人才池`
- `暂缓，先核实风险`
- `排除`

## 招聘状态口径

为避免把历史招聘或聚合页面误认为当前岗位，输出统一使用以下状态：

- `开放-已验证入口`
- `开放-第三方在招，官网未核`
- `需确认-未限定届别`
- `届别不符-仅下一届`
- `已截止-仅历史招聘`
- `持续招聘信号-无具体岗位`
- `未知-需联系HR`

## 来源和事实表达

来源按证据强度分为三层：

1. **一手或权威来源**：政府公示、交易所公告、公司和投资方官网、官方招聘页、客户官网；
2. **可信二手来源**：高校就业网、行业协会、研究机构、主流招聘平台、可信行业媒体；
3. **弱信号**：聚合页、员工评论、论坛和社交帖子，只用于发现候选或提示风险。

关键事实会标记为：

- `已核实`
- `合理推断`
- `公司自述`
- `未核实`

A 档、H3 或“立即投递”的公司，原则上需要至少两类独立来源，并至少包含一个一手或权威来源。

## 输出内容

一次完整结果通常包含：

1. 用户画像、检索日期、地理范围和关键假设；
2. H2/H3 公司行动总表；
3. 优先公司的完整证据卡片；
4. H1 潜力观察池；
5. 少量排除示例及原因；
6. 不属于“小而美”的大平台备选；
7. 每家优先公司的定向搜索词；
8. 第一批、第二批投递顺序；
9. 简历关键词和项目包装建议；
10. 面试前需要核验的问题；
11. 搜索限制和信息缺口。

核心判断链为：

```text
为什么适合用户 → 为什么值得关注 → 小而美证据是否成立 → 当前是否可投 → 下一步行动
```

## 使用方法

显式调用：

```text
$find-hidden-gem-employers
我是 27 届软件工程硕士，想找 AI 应用开发和 Agent 相关工作，
工作地点为河南、安徽、江苏、浙江、广东，排除外包和长期驻场。
```

更完整的请求示例：

```text
$find-hidden-gem-employers
我是 2027 年毕业的软件工程硕士，熟悉 Java、Spring Boot、Python、
LangChain、RAG 和 Docker。希望在苏州、杭州、合肥或深圳寻找 AI Agent
应用开发、AI 后端或工业智能相关岗位。偏好 50–2000 人的产品型公司，
不接受人力外包和长期驻场，可以接受少量出差。请给出当前可投岗位、
小而美证据、投递顺序、风险和面试前核验问题。
```

也可以只询问方法，不生成实时公司名单：

```text
$find-hidden-gem-employers
解释你如何判断一家企业是不是“小而美”，以及如何避免把合作关系误写成投资关系。
```

## 建议提供的信息

信息越完整，结果越贴近个人情况：

- 毕业年月，而不只是届别；
- 学历和专业；
- 目标城市；
- 目标岗位及优先级；
- 编程语言、框架和工程工具；
- 项目、论文、竞赛或实习；
- 可接受的公司规模和阶段；
- 是否接受出差、驻场、实施或定制交付；
- 是否需要解决户口、人才补贴或签约时限问题。

## 设计原则

- **最新信息优先**：具体公司和岗位必须联网核验；
- **证据优先**：宣传语不能替代资质、产品、客户和招聘证据；
- **届别优先**：历史招聘只能证明招聘偏好，不能证明当前可投；
- **行动优先**：输出必须能指导立即投递、联系 HR 或暂缓；
- **宁缺毋滥**：不为凑够公司数量而降低 H2/H3 门槛；
- **关系准确**：投资、控股、孵化、客户、合作和团队履历分别表述；
- **风险透明**：没有发现公开风险不等于不存在风险。

## 局限

- 招聘页面可能需要登录，或在短时间内关闭；
- 部分公司不公开团队人数、客户结构和研发收入；
- 招聘聚合站的发布日期和岗位状态可能不准确；
- 非上市公司的股权和融资信息未必完整；
- 搜索结果受网页收录、地区信息透明度和检索日期影响；
- Skill 提供求职调查和决策支持，不构成对公司经营、劳动条件或 Offer 质量的保证。

## 维护与扩展

调整评分、H 等级或风险规则时，优先修改 `references/evaluation.md`；调整最终报告结构时，修改 `references/output.md`。`SKILL.md` 应保留核心工作流和路由，避免把所有细节重复堆叠在入口文件中。

提交修改前建议运行 Codex Skill 校验器：

```bash
python <skill-creator目录>/scripts/quick_validate.py ./find-hidden-gem-employers
```

校验通过只说明目录结构和元数据有效；它不能替代真实联网任务的行为验证。
